## Restore Result

Status: `BLOCKED`

The custom-format archive was readable, but a complete transactional restore could not be produced without altering the restore catalog beyond the approved narrow safety boundary.

Sanitized root-cause sequence:

1. Restoring into the image's default database collided with the image-initialized `auth` schema.
2. A clean restore was not valid under the non-superuser `postgres` role because an existing PostgREST event trigger had a different owner.
3. A fresh `template0` database removed the pre-created schema collision, but the image's `postgres` role is intentionally not a superuser and could not restore a function-level PostgreSQL setting.
4. Re-running the empty-database restore with the image's isolated `supabase_admin` superuser revealed that the archive independently contains objects also generated by the `supabase_vault` extension.
5. One exact duplicate extension function was excluded in a temporary restore catalog as a minimal diagnostic. The next restore revealed a second independent duplicate extension view. At that point the rehearsal stopped instead of adding broader unreviewed archive filters.

All failed restore attempts used `--single-transaction`, so each failed attempt rolled back. No restored production data was left behind.
