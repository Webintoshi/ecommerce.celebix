# Shared Trendyol Implementation Plan

> **For agentic workers:** Use scoped implementation briefs and an independent final review. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a native, package-gated Trendyol integration with store-specific price protection, catalog synchronization and orders in the existing order screen.

**Architecture:** Shared native SQL/functions and encrypted seller credentials; bounded durable workers and authenticated callbacks; existing native order/inventory readers; per-provider adapter boundaries.

**Tech Stack:** Next.js16, React19, TypeScript, PostgreSQL16, existing pg/crypto/native contracts. No new dependencies.

**Spec:** docs/superpowers/specs/2026-10-23-trendyol-design.md

## Global Constraints

- Release owner root; baseline14d4df3276b842fd4d907d927e99c2db271df373.
- Enforce current `marketplaces` plan feature, including server/workers. Preserve immutable historical tariff snapshots.
- Website amounts are integer cents; rates basis points. Never change storefront prices.
- Secrets tenant-bound encrypted, never logged or echoed. No live seller actions without deliberate connection/mapping.
- No browser polling or network inside DB transactions. Coalesced jobs, generation fences and small bounded batches.
- Preserve customer/order/payment/stock flows and retained financial history. Never fabricate bank cash.
- Exact candidate signup proof required before any deployment. NET then SITE acceptance.

## Review Focus

- Changed credentials or plan downgrade during a job must invalidate completion and prevent new external writes.
- Replayed/split/out-of-order package changes must not duplicate logical orders or stock consumption.
- Price rounding and commission VAT must preserve the configured cash target without mislabeling profit.
- Missing variant/stock/quota leaves a visible retryable error and retained external identity.
- Backfill and relay buyer addresses must not trigger duplicate transactional or marketing emails.
