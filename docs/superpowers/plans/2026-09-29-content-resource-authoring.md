## Repository decisions and interface map

### Existing boundaries to preserve

- `MerchantAdminRecord` remains the strict `{id,kind,name,config,status,version,createdAt,updatedAt}` DTO; `MerchantAdminRepository.save(SaveMerchantAdminInput)` and `.archive(ArchiveMerchantAdminInput)` retain their signatures and result shapes.
- Latest merchant SQL save wrapper is migration074's `merchant_admin_save`, delegating prior kind-specific wrappers. Wrap that actual current function in new migration174; do not reconstruct migration036/040 as the current implementation.
- Public V1 remains `PublicStorefrontContentRepository.getPage?({hostname,now,slug}):Promise<PublicContentPage>` and `saas.public_content_page_get(text,timestamptz,text)`, with its exact five-field response. Its implementation may read the body sidecar after migration174 so an old compatible storefront can render newly saved long bodies without extra DTO keys.
- `ContentAuthoringRepository.beginGeneration(BeginContentGenerationInput)` keeps its TypeScript signature. Only its SQL target changes to the additive `saas.content_authoring_begin_shared` after Task4; original `saas.content_authoring_begin` remains callable/defined identically for old deployments until rollout compatibility is confirmed.
- Reuse policy-editor mechanisms from `PolicyBodyField.tsx`/`policy-body-editor.ts`, not the product's size limit. Do not convert policy domain keys, policy100,000-byte limits or all generic editors in this phase.

### New shared contracts (defined in Tasks1/4/5)

Use `Readonly` fields throughout; parsers reject non-plain prototypes, accessors without invoking them, symbols/non-enumerable extras, sparse arrays, invalid UTF-8/unpaired surrogates and unexpected keys.

- `MerchantContentKind = 'blog_post' | 'page'`.
- `MerchantContentField = 'name' | 'body' | 'excerpt' | 'seoTitle' | 'seoDescription'`.
- `MerchantContentValues = {name:string;slug:string;locale:string;body:string;excerpt:string|null;seoTitle:string|null;seoDescription:string|null;published:boolean;status:'draft'|'active'}`. Full snapshot; all keys required. `body:''` explicitly clears; nullable metadata clears via null. Omission is invalid, never fallback to saved values.
- `MerchantContentDocument = Omit<MerchantContentValues,'status'> & {id:string;kind:MerchantContentKind;status:'draft'|'active'|'archived';version:number;publishedAt:string|null;createdAt:string;updatedAt:string;bodyFormat:'legacy'|'normalized_html';bodyDigest:string;origins:MerchantContentOrigins}`. `bodyDigest` is `sha256:<64 lowercase hex>` over the exact authoritative stored UTF-8 body bytes, including legacy bytes; it is not a digest of the generic compatibility projection.
- `MerchantContentOrigins = Partial<Record<MerchantContentField,{generationId:string;state:'ai'|'edited_ai'} | {state:'manual'}>>`. Applied refs are claims; SQL computes field hashes/classification and resolves durable lineage itself. Missing origin on a normal subsequent edit preserves persisted lineage; an explicit valid manual restore restores current classification without deleting history.
- `SaveMerchantContentRequest = {draftId:string;recordId:string|null;expectedVersion:number|null;expectedBodyDigest:string|null;kind:MerchantContentKind;bodyAction:'replace'|'preserve';values:MerchantContentValues;origins:MerchantContentOrigins}`; new ID/version/body digest all null, existing all supplied. An existing save checks both expectedVersion and expectedBodyDigest against the locked authoritative document; mismatch returns version_conflict. The body digest is a read-consistency guard, not permission or a secret. HTTP operationId is idempotency header, tenant/actor/time come only from server. New documents require bodyAction=replace. Preserve is allowed only for an existing exact-version body echo equal to current stored bytes and unchanged body origin; SQL preserves that source/format explicitly. Thus editing SEO on unsupported legacy text does not force a destructive conversion or use an omitted-field fallback.
- `MerchantContentVersion = {recordId:string;kind:MerchantContentKind;version:number;values:Omit<MerchantContentValues,'status'>;status:'draft'|'active'|'archived';bodyFormat:'legacy'|'normalized_html';origins:MerchantContentOrigins;savedAt:string}`. Read saved sidecar snapshots; adapt older immutable saved events to this view without updating those events. Version lacking a recoverable historical body is explicitly unavailable, never replaced with the current body.
- `ContentResourceTarget = {kind:MerchantContentKind;draftId:string;recordId:string|null;recordVersion:number|null}`.
- `ContentOutline = {title:string;sections:readonly {heading:string;points:readonly string[]}[]}`;1–12 sections,0–6 points/section; title160UTF-8 bytes, headings200bytes, points500bytes, complete outline≤8,192bytes.
- `ContentResourceRequestBase = {target:ContentResourceTarget;currentDraft:MerchantContentValues;locale:string;tone:'neutral'|'friendly'|'professional';brandVoice?:string|null;length:'short'|'medium'|'long';note:string;researchOperationId:string|null}`. Note≤2,000bytes, voice≤160UTF-16 code units and no controls as Phase1; currentDraft supplies all unsaved fields.
- `ContentResourceAuthoringRequest = (ContentResourceRequestBase & {stage:'outline';topic:string;purpose:string}) | (ContentResourceRequestBase & {stage:'draft';action:'article'|'improve'|'shorten'|'rewrite_selection'|'seo';fields:readonly MerchantContentField[];reviewedOutline:ContentOutline|null;outlineGenerationId:string|null;selection:{field:'body';text:string}|null})`. Topic500bytes/purpose1,000bytes. Article requires both reviewedOutline and completed same-actor/target outlineGenerationId; modified reviewed outlines are allowed and fingerprinted. Other actions require both null unless explicitly article. No automatic outline→article call.
- `ContentResourceDraft = {sourceFingerprint:string;values:Partial<Pick<MerchantContentValues,MerchantContentField>>;citations:readonly ContentCitation[];suggestions:readonly string[]}`; exactly requested fields. Body originates as validated structured blocks, then escaped rendered HTML. `ContentCitation={field:MerchantContentField;sourceId:string;quote:string}` where quote≤512bytes and exact normalized substring of retained server source text; model-supplied URLs never create sources.
- `ContentResourceGeneration` mirrors Phase1 operation status/binding/claim/usage fields but has `target`, `stage`, `outline:ContentOutline|null`, `draft:ContentResourceDraft|null` instead of productId/product draft. `ContentResourceGenerationView` excludes claimToken/provider secrets. Product types do not gain content IDs.
- `ContentResearchRequest={target:ContentResourceTarget;urls:readonly string[]}`; no implicit search/crawl. `ContentResearchSource={id:string;originalUrl:string;finalUrl:string;title:string;fetchedAt:string;contentSha256:string;extractedText:string;byteCount:number}`. Public-to-merchant view omits extractedText by default; article service reads it privately. `ContentResearchResult={operationId:string;status:'pending'|'completed'|'failed'|'unknown';sources:readonly Omit<ContentResearchSource,'extractedText'>[];usage:{sourcesAttempted:number;fetchedBytes:number;extractedBytes:number;elapsedMs:number};safeCode:string|null}`.

### Limits and choices not numerically fixed by the spec

- New replacement-body parser returns normalized safe HTML and rejects unsafe markup/link schemes; published=true requires status=active; new replacement writes accept empty body, including already-published legacy empty pages. Preserved legacy reads validate bounded Unicode bytes and render safely without treating legacy markup as newly approved write input. For legacy unsupported structure, preserve original read-only source until explicit conversion; do not quietly sanitize-and-save it.
- `name`1–160UTF-8 bytes; slug1–100 lower-case ASCII hyphen-separated; locale follows existing `[a-z]{2,3}(?:-[A-Z]{2})?` convention≤35bytes. Excerpt≤4,000bytes; SEO title≤160bytes and description≤4,000bytes plain text, matching existing content SEO storage conventions without joining its records. UI SEO targets remain suggestions, not hard padding requirements.
- New save/generate HTTP wire ceiling786,432bytes accommodates JSON escape expansion. Canonical decoded save envelope≤131,072bytes; body still≤80,000bytes after normalization. Existing generic/product endpoints keep their ceilings.
- Separate provider input profile `content_resource` allows131,072UTF-8 input bytes,8,192output tokens,131,072raw JSON output bytes,393,216serialized provider-request bytes and786,432provider-envelope bytes;45-second total generation deadline. Existing chat/product profile limits are unchanged. Initial resource-profile capability is explicitly DeepSeek `deepseek-flash` only, matching the Phase1 evaluated provider/model; other selected providers/models fail with a visible unsupported-capability code before dispatch until separately tested. Verify its current official output/context limits during implementation before enabling this profile;8,192 is the planned application ceiling, not an unverified claim about every model. No fallback or chunked automatic extra paid calls. Body storage capacity is not a promise to generate80,000bytes in one call. If full current body plus research/outline exceeds the model-input envelope, fail visibly before dispatch and let the user select a smaller scope; never silently truncate or substitute saved content. Manual80,000-byte saves remain supported.
- Research: explicit1–3 canonical HTTPS URLs, at most3manual redirects each,524,288raw bytes/source,12,000extracted UTF-8 bytes/source and32,000combined bytes,10seconds/source and20seconds overall including DNS/stream/extraction. HTML or plain UTF-8 text only, identity encoding only; scripts/styles/templates/forms/navigation are excluded from extracted text. Extraction limit exceedance fails with a visible safe code instead of silent truncation. No assets/subresources/robots discovery/crawler/provider tools. Fetch bytes/time/count are recorded; inference usage remains separate/null when absent and unpriced money is never shown as zero.
- Shared model-attempt allowance keeps existing store100/day configurable limit,6/minute actor+store and1active actor+store across product/content. Outline and article are each a visible generation attempt. Research additionally permits10requests/store/day and6/minute actor+store, sharing the1active-operation admission lock; its retrieval usage is separate from model tokens.
