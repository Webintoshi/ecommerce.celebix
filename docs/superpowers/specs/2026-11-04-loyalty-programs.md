# Shared loyalty programs

Approved by the merchant on 4 November 2026. Build four ready campaign templates under Discounts > Loyalty Programs: eligible product units to a specified gift variant; distinct purchases to a gift; cumulative eligible merchandise spend to a fixed discount; qualifying purchases to free standard/selected shipping. No VIP tiers or separate points wallet.

Programs use three progress measures and three reward types. Save starts the real program (or schedules its specified start). Existing promotion permissions and plan entitlement apply. Existing discounts and payment workflows remain intact. Managers can edit, duplicate, pause, report and record audited corrections. Cashier access requires an explicit permission and verified customer approval.

Only authoritative paid eligible merchandise earns progress; partial credit sales wait until fully collected. Zero-cash debt forgiveness is not a payment. Gifts and shipping do not earn. Marketplace imports and a WhatsApp click are excluded. No historical retroactive grants. Use a verified storefront account and stable tenant/customer identity, never merge histories by a matching mutable contact phone. Web and POS share the same member after explicit verified approval.

Repeat is on, excess progress carries forward, one reward per order and no stacking by default. Multiple-program earning is an explicit choice. Progress/rewards do not expire by default; optional expiry is separate from earning schedule. Pause stops new earning while preserving existing rewards. Capture earning/reward rule versions; edits and returns compensate original effects. Already used rewards remain in history and offset later earning, without creating cash debt. Deleting an order alone is not a refund.

Rewards are usable on later purchases. A specified gift may be redeemed alone; preserve stockout entitlement, never substitute variants. Unknown bank outcomes retain reward reservations even when an ordinary hold expires. Failures release only after definitive settlement. Any number of browser tabs remains usable; a reward is spent once. Zero-total orders covered by an applied, verified, owned loyalty reward validate stock and create a real completed order without a zero-value bank charge or fabricated cash receipt. This includes a fixed discount that covers the entire eligible basket; ordinary coupons cannot enter this loyalty-only payment method.

Reuse promotion stock/tax/refund snapshots. One managed promotion per program version and one owner-bound single-use code per earned reward. Bound active program/version count below the existing 100-promotion evaluator ceiling. Use an indexed transactional work queue and append-only source effects, not full-history scans on each request. Reports show progress, earned/used/available rewards and known costs, without inventing missing costs.

Panel follows existing campaign cards and a three-step form: target/reward, conditions, preview/start. Customer account shows progress and a direct Use reward action. Keep the admin shell fixed and use the existing orange/white control design.

First-release return policy: existing accounting facts record returned money, without an authoritative product-line/quantity allocation. Programs based on units, purchases, or selected-product spend therefore exclude a purchase after an actual recorded return; a permitted manager may apply an audited progress correction. All-product spend uses the known net returned merchandise amount. Never infer returned quantities or selected-product attribution from a monetary ratio. A cash refund for a price adjustment or order deletion alone is not an actual product return. Show this condition in setup and preview. Used reward history remains intact and no cash debt is created.

Initial shared rollout is closed to new loyalty mutations through a private owner-only readiness row until owner, storefront and panel NET/SITE applications all run the admitted candidate. Lists and exact operation recovery/replay remain available; rejected setup writes create no operation. This prevents loyalty sale data reaching an old strict panel consumer during deployment. The operator opens readiness once after all six live acceptances. After opening, fixes roll forward; pre-loyalty panel rollback is incompatible with redeemed loyalty records. Merchants retain the direct-save workflow without an additional activation step.
