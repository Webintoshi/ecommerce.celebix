# Google Bağlantıları — ortak pazarlama
Date: 2026-10-08
## Authorized outcome
Pazarlama > Google Bağlantıları at /marketing/google for every tenant. Three provider cards: gtm, ads, search_console. No reports or arbitrary code editor. Uygula saves and activates; Vazgeç preserves. Google OAuth authenticated account selection, per-store authorization and encrypted server credentials. Existing authorized platform support may configure current store and is audited as real operator.
## Connection behavior
Google OAuth centrally configured once; callback uses configured PANEL origin (one canonical origin for the shared app cohort), validates originating merchant store host and allowlisted return host. Fixed Google callback /api/marketing/google/callback serves a minimal no-store completion page; same-origin POST /api/marketing/google/complete rechecks merchant/support session. This avoids support SameSite=Strict cross-site loss. State is unpredictable, stored hashed, one use, actor/store/session bound, 10-minute expiry. Google code and credentials never logged or exposed beyond that transient callback. Required service scopes only; access/refresh tokens encrypted, unavailable crypto blocks writes. Google identities verified through Google userinfo; account list is not tenant ownership proof.
GTM: choose accessible web container or create a named store container inside an accessible account. Google readonly for selection; incremental edit/version/publish scopes needed only for automatic installation. Preserve existing tags; configure only recognizable Celebix entities, detect live-version conflicts, apply publishes changes directly with explicit summary, safe retry uses operation key. Ads: discover accessible advertiser accounts (manager hierarchy capped), choose a manual website purchase conversion and use actual AW conversion destination and label (not customer ID). No campaign/budget/billing mutations. Search Console: existing correct site or create URL-prefix for the store primary verified domain using meta verification, sites.add and sitemap submit. No arbitrary domain fetches. Domain property creation is not required.
## Public storefront
Public projection contains only validated GTM container ID, optional AW conversion settings and verification token. Storefront loads a single GTM runtime only after explicit analytics/advertising consent; controlled Google native tag policy rejects Custom HTML/JS, no unsafe-eval or unrestricted wildcard CSP. Shared SPA commerce adapter emits view_item/add_to_cart/begin_checkout from approved state, without contact PII. Purchase derives from authoritative completed WEB payment, stable transaction ID, real value/currency; never thank-you-page truth, never POS. Respect existing native analytics/stock/payment behavior. Empty integrations load no extra Google scripts.
## Reliability and performance
Lazy account discovery only when setup opens; bounded Google requests with timeouts, redacted errors, no routine polling. Each connection and operation store-bound, optimistic version + Idempotency-Key, duplicate apply and callbacks cannot create duplicate tags or grant extra access. Back/disconnect/retry operates only on current store; permissions revoked and missing platform setup are explicit states. Google service/approval limits are external prerequisites, not fake success.
## Public interface
GoogleMarketingService = gtm | ads | search_console.
Overview = {storeDomain:string, oauthConfigured:boolean, connections:Connection[]}.
Connection = {service, version:number, status:disconnected|connected|needs_reconnect|error, googleEmail:string|null, selection:Selection|null, lastCheckedAt:string|null, errorCode:string|null}.
Selection = {accountId:string, resourceId:string, resourceName:string, tagId?:string, conversionLabel?:string, create?:boolean}.
ResourceOption = {id:string,name:string,parentId?:string,tagId?:string,conversionLabel?:string}.
Resources = {accounts:ResourceOption[],resources:ResourceOption[],nextPageToken?:string}.
Repository/service: overview({tenantContext,now}); begin({tenantContext,service,operationId,sessionBinding,returnOrigin,now})->{authorizationUrl}; complete({tenantContext,sessionBinding,state,code,now})->{returnOrigin}; resources({tenantContext,service,accountId?,now}); apply({tenantContext,service,expectedVersion,selection,operationId,now}); disconnect({tenantContext,service,expectedVersion,operationId,now}); publicProjection(storeId).
HTTP: GET /api/marketing/google; POST /api/marketing/google/connect; GET /api/marketing/google/resources?service=&accountId=; POST /api/marketing/google/apply; POST /api/marketing/google/disconnect; GET callback; POST complete. Same-origin writes, integrations.read/manage, store resolved from host+session, no caller-selected tenant. JSON failures {code}, no secrets.
