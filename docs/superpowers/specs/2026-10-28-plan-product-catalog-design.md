# Productized package purchase

The merchant's task is to compare four real Celebix packages and continue to the existing correct purchase or package-change flow. Use the supplied pricing-card/table references, the existing Urbanist/theme tokens and a coherent generated luxury product-art family.

## Design

Compact current-plan/usage strip → monthly/annual control → four image-led selectable product cards → selected-product/payment summary → full comparison. The summary must precede the long table. Desktop four columns where readable, intermediate two, mobile one. Comparison overflow stays inside its own keyboard-accessible region. No repeated visible page heading, invented popularity claims or pricing changes.

## Approach and constraints

Reuse existing catalog, permissions, idempotent checkout, manual change requests and fulfillment. Presentation-only product mapping and versioned static WebP assets require no schema/API change. Keep frozen historical agreements and existing paid-store rights; do not invent paid-upgrade proration. Free owners with commerce enabled purchase through the existing signed handoff. Paid upgrades retain accurate existing request controls. Staff/support never gain purchase rights. No real card charge during QA.

Prices, period labels, annual equivalents, net/VAT/total and selected product must agree. Do not claim four independent root domains from the hostname-slot limit; label the capability as “Özel alan adı”. Checkout must use the selected offer's image with a safe fallback for unknown historical offers.

Render and inspect desktop/tablet/mobile, keyboard controls, contained table scrolling, actual asset loading and purchase-page-only navigation.
