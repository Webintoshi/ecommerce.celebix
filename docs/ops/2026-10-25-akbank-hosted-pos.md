# Akbank 3D Pay Hosting integration

## Scope

The shared integration uses `akbank_json` for Akbank's modern **3D Pay Hosting** product. The older classic Akbank variant remains planned. The supported customer flow is standard cart and buy-now checkout, TRY, Turkish/English and one installment. Existing quick-order payment links remain iyzico-only. Refund, void and preauthorization APIs are not advertised by this adapter.

Merchant Safe ID, Terminal Safe ID and the existing Secret Key are write-only encrypted merchant-profile credentials. The public profile contains environment and a safe account label only. Browser presentation contains only the bank's exact 29 approved form fields, derived transaction MAC and operation-bound return URL. Celebix never collects PAN/CVV.

## Payment authority

- Bank-hosted transaction3000 performs authentication and sale. There is no second authorization request.
- The signed bank orderId is the immutable checkout attempt UUID, within the bank's36-character limit.
- Browser returns are authenticated against the merchant, terminal, attempt and amount. Only a subsequent authenticated read-only1010 inquiry can produce paid settlement.
- Response HMAC authenticates the original bytes before JSON interpretation. Raw numeric financial/identity tokens are compared exactly; rounding cannot authorize a different amount.
- Unknown results remain processing and use bounded scoped inquiry reconciliation. Replays and callback/query races reuse the recorded attempt and native exactly-once settlement.
- Another active payment provider is an explicit conflict; configuration does not silently replace it.

## Documented not-found responses

The official Akbank error table defines `VPS-1123` as transaction not found. It is recognized only through the existing authenticated `1010` response path: HTTP200 JSON, a valid HMAC over the original bytes, and the expected merchant/terminal identity. Credential verification additionally requires an absent or empty transaction list. Missing or invalid signatures, malformed lists and unrelated error codes remain inconclusive. In payment inquiry/callback handling, not-found remains pending and never authorizes paid settlement.

Changing merchant, terminal or secret values requires a fresh encrypted credential version and normal worker verification. An active terminal in the bank portal alone is not proof of successful hosted payment.
